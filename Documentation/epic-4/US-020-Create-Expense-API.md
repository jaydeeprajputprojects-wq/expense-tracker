# US-020 — Create Expense API

**Project:** Personal Finance & Money Flow Tracker  
**Feature:** Epic 4 — Transaction Management Backend  
**User Story:** US-020  
**Estimated Effort:** 4 hours  
**Status:** Implementation Documentation

---

## 1. User Story

**As a user,** I want to create an expense transaction through the backend API, so that the application can persist valid expense entries and return a transaction ID for downstream workflow steps.

### Acceptance Criteria

1. The API accepts a valid expense payload.
2. The request includes a valid transaction date.
3. The request includes a valid amount greater than zero.
4. The category must exist in the master data.
5. The payment method and paid-from account must be valid.
6. The API rejects invalid requests with a structured error response.
7. The backend generates a transaction ID server-side.
8. The transaction is saved with `Status = ACTIVE`.
9. The API returns the created transaction ID in the success response.

---

## 2. Business Goal

Expense creation is the primary write operation for transaction management. It ensures that valid business data is saved into the transaction ledger and that financial impact is tracked consistently after the record is written.

The backend must validate the request before saving, because invalid data could create ledger inconsistencies and distort account balances.

---

## 3. API Contract

### Request

```json
{
  "action": "CREATE_TRANSACTION",
  "data": {
    "transactionType": "EXPENSE",
    "transactionDate": "21-09-2026",
    "amount": 2500,
    "categoryId": "CAT001",
    "paymentMethod": "BANK",
    "paidFromAccountId": "ACC001",
    "notes": "Groceries"
  }
}
```

### Success Response

```json
{
  "success": true,
  "message": "Transaction created successfully",
  "data": {
    "transactionId": "TXN-20260921-1A2B3C"
  }
}
```

### Error Response

```json
{
  "success": false,
  "error": {
    "code": "INVALID_PAYMENT_METHOD_ACCOUNT",
    "message": "Paid from account must match the selected payment method."
  }
}
```

## 4. Validation Flow

The API route receives the request and calls the validation layer before persistence.

```javascript
if (!request || !request.data) {
  return ResponseUtil.error('INVALID_REQUEST', 'Request data is required');
}

const validation = ValidationService.validateTransaction(request.data);

if (!validation.valid) {
  return ResponseUtil.error(validation.code, validation.message);
}
```

The validation is centralized in:

```javascript
ValidationService.validateTransaction(data)
```

This dispatches to the correct rule set based on the transaction type.

---

## 5. Server-Side Transaction ID Generation

The backend must generate the transaction ID instead of the frontend.

The implementation uses the current date and a random identifier suffix.

```javascript
function generateTransactionId_() {
  const today = new Date();
  const datePart = [
    today.getFullYear(),
    String(today.getMonth() + 1).padStart(2, '0'),
    String(today.getDate()).padStart(2, '0')
  ].join('');

  const randomPart = String(Utilities.getUuid())
    .replace(/-/g, '')
    .slice(0, 6)
    .toUpperCase();

  return 'TXN-' + datePart + '-' + randomPart;
}
```

This ensures the ID pattern remains aligned with the design contract:

```text
TXN-YYYYMMDD-XXXXXX
```

## 6. Persistence Model

Once validated, the backend creates a transaction record in the `Transactions` sheet with the following core fields:

- `Transaction_ID`
- `Transaction_Date`
- `Transaction_Type`
- `Amount`
- `Category_ID`
- `Payment_Method`
- `Paid_From_Account_ID`
- `Received_Into_Account_ID`
- `From_Account_ID`
- `To_Account_ID`
- `Notes`
- `Created_Date`
- `Updated_Date`
- `Status`

The record is written with:

```javascript
Status: 'ACTIVE'
```

## 7. Transaction Creation Result

After the record is appended, the service returns a structured object:

```javascript
return {
  success: true,
  transactionId: transactionId,
  record: transactionRecord
};
```

The API layer then standardizes it as:

```javascript
ResponseUtil.success(
  { transactionId: created.transactionId },
  'Transaction created successfully'
);
```
